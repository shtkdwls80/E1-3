# MAC 필터 판정 애플리케이션

## 실행 방법
- Python 3.8 이상 필요 (표준 라이브러리만 사용, 외부 라이브러리 없음)
- 실행: `python main.py`
- 모드 선택: 실행 후 `1`(사용자 입력 3×3) 또는 `2`(data.json 분석) 입력
- `data.json`은 `main.py`와 같은 디렉터리에 위치해야 함

## 구현 요약
- **라벨 정규화**: 내부 표준 라벨은 `Cross`, `X` 두 가지.
  expected의 `+`→`Cross`, `x`→`X`, 필터 키 `cross`→`Cross`, `x`→`X`로 통일.
- **MAC 연산**: 패턴과 필터를 위치별로 곱해 모두 더함. 이중 for문으로 직접 구현(라이브러리 금지).
- **동점 처리(epsilon)**: `abs(score_cross - score_x) < 1e-9`이면 `UNDECIDED`.
  그 외에는 점수가 큰 쪽의 표준 라벨을 판정값으로 사용.

## 결과 리포트
### 실패 원인 분석
1. **스키마 오류**: `input` 또는 `expected` 키가 없는 케이스는 FAIL 처리.
2. **크기 불일치**: 키에서 추출한 N과 필터 크기가 다르면 `ValueError`를 잡아 케이스 단위 FAIL.
   (예: `size_7_0`은 `size_7` 필터가 없어 FAIL, 프로그램은 계속 진행됨)
3. **라벨/정규화 실패**: 알 수 없는 라벨은 정규화 결과가 `None`이 되어 FAIL.
4. **부동소수점**: float 점수의 미세 오차는 epsilon(1e-9)으로 흡수하여 오판정을 방지.
5. **비교 정책**: PASS/FAIL은 반드시 표준 라벨(Cross/X) 기준으로 비교하여 표기 차이로 인한
   거짓 실패를 제거.
- 정상 케이스에서 FAIL이 0인 이유: 정규화로 라벨 불일치가 사라지고, epsilon으로 동점/오차가
  정리되며, 패턴이 각 필터와 정확히 매칭되도록 구성했기 때문.

### 성능 표 해석 + O(N²) 근거
- MAC 연산은 n×n 모든 위치를 1회씩 방문하므로 연산 횟수는 **N²**(곱셈+누적)이다.
- 따라서 시간 복잡도는 **O(N²)**.
- 측정 결과에서 N이 3→5→13→25로 커질 때 평균 시간이 대체로 N²에 비례해 증가하는 경향을
  확인할 수 있다(3×3=9회, 5×5=25회, 13×13=169회, 25×25=625회).
- 작은 크기는 측정 오버헤드 영향이 커서 비례가 다소 흔들릴 수 있으나, 크기가 커질수록
  N² 비례 경향이 뚜렷해진다.

## 재현성
- 모드 1: 3×3 Cross/X 필터와 패턴을 입력하면 점수/판정/시간이 출력됨.
- 모드 2: `data.json` 분석 시 케이스별 PASS
